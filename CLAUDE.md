## Commands

```bash
npm start                # expo start (dev server, Metro)
npm run android          # expo start --android
npm run ios              # expo start --ios
npm run web              # expo start --web
npm run start:lan        # LAN host bound to interface en10 + cache clear (-c); physical-device testing
npm run lint             # expo lint (ESLint flat config, eslint-config-expo)
npx tsc --noEmit         # type check (strict: true)
npm run reset-project    # DESTRUCTIVE: moves app/ to app-example/ and scaffolds a blank app/
```

There is no test framework in this project. Lint and type check are the only automated checks.

`start:lan` hardcodes `en10` via `ipconfig getifaddr en10`. On a machine where the active interface differs (`en0` for Wi-Fi is common), the command fails and the interface must be adjusted.

## Architecture

Expo SDK 54 app (`expo-router` v6, React Native 0.81, React 19, New Architecture enabled, React Compiler enabled via `experiments.reactCompiler`). Single purpose: receive Expo push notifications and deep-link into a chat screen from the notification payload.

### Push notification flow

All notification logic lives in one hook, `hooks/use-push-notifications.ts`. It is the file to read first.

1. Module scope: `Notifications.setNotificationHandler` sets foreground display behavior (banner, list, sound, badge).
2. On mount: `registerForPushNotificationsAsync()` creates the Android `default` channel, requests permission, and gets the Expo push token using the EAS `projectId` read from `Constants.expoConfig.extra.eas.projectId` (falls back to `Constants.easConfig.projectId`). Errors go through `handleRegistrationError`, which alerts and throws.
3. Two listeners: `addNotificationReceivedListener` prepends to the `notifications` state array; `addNotificationResponseReceivedListener` fires when a notification is tapped and stores `data.chatId` into `pendingChatId`.
4. Cold start (app was terminated): `Notifications.getLastNotificationResponse()` is read synchronously in the same effect, so the tap that launched the app is not lost.
5. Navigation is deferred. A separate effect waits for `useRootNavigationState().key` to exist before calling `router.push('/chat/<id>')`. Navigating before the root navigator mounts throws, so keep this gating when changing routing. The `as Href` cast is needed because typed routes do not accept the interpolated string.

`sendPushNotification` posts directly to `https://exp.host/--/api/v2/push/send` from the client. It exists for manual testing; the send button in `app/index.tsx` is commented out.

To trigger the deep link, the push payload must carry `data: { chatId: "<string>" }`. Any other shape is ignored.

### Routing

File-based, `app/` directory, typed routes enabled (`experiments.typedRoutes`), so `.expo/types` must be regenerated by the dev server after adding a route.

- `app/_layout.tsx` — root `Stack` inside `@react-navigation/native` `ThemeProvider`. Background color comes from `useThemeColor`, not from the navigation theme.
- `app/index.tsx` — token display plus a `FlatList` of received notifications.
- `app/chat/[id].tsx` — deep-link target, reads `id` via `useLocalSearchParams`.

`app/_layout.tsx` still exports `unstable_settings = { anchor: '(tabs)' }` from the create-expo-app template, but there is no `(tabs)` group in this project. It is stale.

### Theming and shared components

`constants/theme.ts` holds `Colors.light` / `Colors.dark` and platform `Fonts`. `hooks/use-theme-color.ts` resolves a color from the active scheme with per-call light/dark overrides; `hooks/use-color-scheme.ts` has a `.web.ts` variant for hydration. Use `ThemedText` / `ThemedView` from `components/` rather than raw `Text` / `View` so both schemes work.

Most of `components/` (`hello-wave`, `parallax-scroll-view`, `external-link`, `haptic-tab`, `ui/collapsible`, `ui/icon-symbol`) is unused create-expo-app template code, not app code.

Imports use the `@/*` path alias mapped to the project root.

## Native config

`app.json` is the single source of config (no `ios/` or `android/` directories — they are gitignored and generated by prebuild). Plugins: `expo-notifications`, `expo-router`, `expo-splash-screen`. Scheme is `pushapp`; EAS project `969f8d73-f705-446a-b2a3-6fab190b0d65` under owner `j2systems`.

`push-firebase-config.json` is a Firebase service account key used for Android FCM v1 credentials. It is gitignored; `push-firebase-config.template` is the placeholder committed in its place.
